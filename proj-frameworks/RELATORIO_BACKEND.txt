RELATORIO DE CRIACAO DO BACKEND - BRAINLOG

Data: 06/05/2026
Projeto: proj-frameworks

1. OBJETIVO

Foi criado um backend real para o projeto BrainLog, substituindo o uso anterior do json-server por uma API em Node.js com TypeScript, Express, Prisma e PostgreSQL.

O backend suporta autenticacao real com JWT, cadastro de usuarios, login, logout, protecao de rotas privadas, cadastro/listagem/filtro de resumos, metricas de dashboard/evolucao e modulo de upload de arquivos.

Na etapa final, o projeto foi reorganizado para uma estrutura mais adequada de monorepo:

- frontend/: aplicacao Vue/Vite
- backend/: API Node/Express/Prisma
- docker-compose.yml: orquestracao de PostgreSQL, API e frontend
- package.json raiz: scripts de workspace para rodar frontend e backend

- A sessao continua persistida no localStorage.

5. ENDPOINTS CRIADOS

5.1. Health check

GET /health

Retorna status basico da API.


5.2. Usuarios

POST /users

Cria um usuario novo.
Valida e-mail unico.
Criptografa senha com bcrypt.
Retorna usuario publico e token JWT.

Campos esperados:
- name
- email
- password
- goal


GET /users?email=...

Consulta usuarios, com suporte a filtro por e-mail.
Nao retorna senha nem passwordHash.


5.3. Autenticacao

POST /auth/login

Autentica usuario por e-mail e senha.
Retorna usuario publico e token JWT.


POST /auth/logout

Rota protegida.
Retorna 204.
O logout efetivo continua sendo feito no frontend removendo token e usuario do localStorage.


GET /auth/me

Rota protegida.
Retorna o usuario autenticado a partir do token JWT.


5.4. Resumos

GET /summaries?ownerId=...

Rota protegida.
Lista os resumos do usuario autenticado.
Valida que o ownerId pertence ao usuario do token.

Filtros opcionais:
- subject
- status
- search


POST /summaries

Rota protegida.
Cria um novo resumo.

Campos suportados:
- ownerId
- title
- subject
- description
- status
- createdAt
- fileNames


PATCH /summaries/:id/status

Rota protegida.
Atualiza o status de um resumo.

Status suportados:
- Novo
- Em revisao
- Em revisão
- Revisado


POST /summaries/:id/files

Rota protegida.
Faz upload real de anexos usando multipart/form-data.
Os arquivos sao salvos no diretorio configurado em UPLOAD_DIR.
Metadados sao salvos na tabela SummaryFile.


5.5. Dashboard e evolucao

GET /dashboard/:ownerId

Rota protegida.
Retorna metricas agregadas do usuario autenticado.

Metricas retornadas:
- total de resumos
- quantidade revisada
- taxa de revisao
- novos nos ultimos 7 dias
- agrupamento por status
- agrupamento por materia
- evolucao mensal dos ultimos 6 meses


6. SEGURANCA IMPLEMENTADA

- Senhas armazenadas com bcrypt, nao em texto puro.
- JWT com expiracao de 7 dias.
- Middleware de protecao para rotas privadas.
- Validacao de dono do recurso por ownerId.
- Rotas privadas retornam 401 quando nao ha token.
- Rotas privadas retornam 403 quando o usuario tenta acessar dados de outro usuario.
- Validacao de payloads com Zod.
- E-mail unico no banco via constraint do Prisma.

10. OBSERVACOES

- O arquivo db.json permanece no projeto apenas como referencia antiga dos dados usados pelo json-server.
- O backend real agora depende de um PostgreSQL configurado.
- E necessario criar um arquivo backend/.env local baseado no backend/.env.example.
- O json-server foi removido das dependencias.
- O modulo de upload salva arquivos no diretorio configurado por UPLOAD_DIR.
- Para producao, o valor de JWT_SECRET deve ser trocado por um segredo forte.
